Permissions
​
To create a function in
Unity Catalog
, you must have all of the following:
USE CATALOG
on the catalog and
USE SCHEMA
on the schema where you create the function
CREATE FUNCTION
privilege on the schema where you create the function
SELECT
on every referenced
Unity Catalog
table or view, plus
USE CATALOG
and
USE SCHEMA
on the catalog and schema that contain it
EXECUTE
on every referenced user-defined function, plus
USE CATALOG
and
USE SCHEMA
on the catalog and schema that contain it
READ FILES
on the
external location
that backs each referenced cloud-storage path, for example
read_files('s3://bucket/path')
READ VOLUME
on each volume referenced through a
/Volumes/...
path, plus
USE CATALOG
and
USE SCHEMA
on the catalog and schema that contain it
These privileges are checked when you create the function. For how statements inside the function body are authorized when the function runs, see
Authorized user and session user
.
In
Unity Catalog
, replacing an existing function with
CREATE OR REPLACE FUNCTION
also requires that you own the function or have
MANAGE
on it, or own or have
MANAGE
on its parent schema or catalog. The usage privileges you also need depend on the object level at which you hold ownership or
MANAGE
. See
Usage privilege requirements for
MANAGE
. The new function definition can require additional privileges on referenced tables, views, functions, and paths.

Parameters
​
OR REPLACE
If specified, an existing function or procedure with the same name is replaced. The new function's signature (number of parameters and parameter types), return type, and body can differ from the existing function's. You cannot specify this parameter with
IF NOT EXISTS
.
TEMPORARY
The scope of the function being created. When you specify
TEMPORARY
, the created function is valid and visible in the current session. No persistent entry is made in the catalog.
IF NOT EXISTS
If specified, creates the function only when it does not exist. The creation of the function succeeds (no error is thrown) if the specified function already exists in the system. You cannot specify this parameter with
OR REPLACE
.
function_name
A name for the function. For a permanent function, you can optionally qualify the function name with a schema name.
If the name is not qualified the permanent function is created in the current schema.
The function name must be a unique for all routines (procedures and functions) in the schema.
function_parameter
Specifies a parameter of the function.
parameter_name
The parameter name must be unique within the function.
data_type
Any supported data type.
For Python,
data_type
is cast to a Python data type according to this
language mapping
.
For a
STRING
data_type
, the default collation is the function
default_collation_name
.
DEFAULT
default_expression
Applies to:
Databricks SQL
Databricks Runtime
10.4 LTS and above
An optional default to be used when a function invocation does not assign an argument to the parameter.
default_expression
must be
castable
to
data_type
.
The expression must not reference another parameter or contain a subquery.
When you specify a default for one parameter, all following parameters must also have a default.
DEFAULT
is supported for
LANGUAGE SQL
only.
COMMENT comment
An optional description of the parameter.
comment
must be a
STRING
literal.
RETURNS
data_type
The return data type of the scalar function.
For Python UDFs, return values should match the declared
data_type
.
For SQL UDF this clause is optional. The data type is derived from the function body if it is not provided.
RETURNS TABLE [ (column_spec [,…] ) ]
This clause marks the function as a table function.
Optionally it also specifies the signature of the result of the table function.
If no column_spec is specified it will be derived from the body of the SQL UDF.
RETURNS TABLE
is supported for
LANGUAGE SQL
and for
LANGUAGE PYTHON
polymorphic UDTFs
(
Databricks Runtime
18.1 and above).
column_name
The column name must be unique within the signature.
data_type
Any supported data type.
COMMENT column_comment
An optional description of the column.
comment
must be a
STRING
literal.
RETURN {
expression
|
query
}
The body of the function. For a scalar function, it can either be a query or an expression. For a table function, it can only be a query. The expression cannot contain:
Aggregate functions
Window functions
Ranking functions
Row producing functions such as
explode
Within the body of the function you can refer to parameter by its unqualified name or by qualifying the parameter with the function name.

You can specify any number of them in any order, but you can specify each clause only once.

Applies to:
Databricks SQL
Databricks Runtime

Declares a batch

[NOT] DETERMINISTIC
Whether the function is deterministic.
A function is deterministic when it returns only one result for a given set of arguments.
You may mark a function as
DETERMINISTIC
when its body is not and vice versa.
A reason for this may be to encourage or discourage query optimizations such as constant
folding or query caching.
If you do not specify this option, the default depends on the function's language.
For SQL functions, it is derived from the function body.
For Python, Scala, and Java functions, the function is
NOT DETERMINISTIC
.
COMMENT function_comment
A comment for the function.
function_comment
must be String literal.
CONTAINS SQL
or
READS SQL DATA
Whether a function reads data directly or indirectly from a table or a view.
When the function reads SQL data, you cannot specify
CONTAINS SQL
.
If you don't specify either clause, the property is derived from the function body.

Specifies the environment for a function declared with

The

A JSON array of strings specifying the required Python packages or wheel files for a

PyPI package with optional version, for example: "simplejson==3.19.3"
Absolute path to a wheel file stored in a

..."
For a dependency stored in a
Unity Catalog

Unity Catalog

java_dependencies
Applies to:
Databricks SQL
Databricks Runtime
18.2 and above
A JSON array of strings specifying the JAR files that contain the compiled code for a
LANGUAGE SCALA
or
LANGUAGE JAVA
function. Each entry is an absolute path to a JAR file stored in a
Unity Catalog
volume, for example: "/Volumes/my_catalog/my_schema/my_volume/packages/my-udf-assembly-0.1.0.jar". Package the code as a fat JAR that includes all third-party dependencies used by the UDF.
environment_version
A string specifying the environment version.
For
LANGUAGE PYTHON

'6'
, or
'None'
. The value
'None'

'None'

18.2 or above. On
Databricks Runtime
16.2 through 18.1, only

On serverless compute and on pro and serverless SQL warehouses, some features require an explicit environment version. Set
environment_version
to the required version or above in each UDF definition. Omitting the clause or setting

Python UDF feature requirements

For classic compute version compatibility, see
Environment versions on classic compute

Environment versions

For
LANGUAGE SCALA
and
LANGUAGE JAVA

'4'
or above. Environment version 4 specifies Scala 2.13.16 and JDK 17. See
Environment versions
