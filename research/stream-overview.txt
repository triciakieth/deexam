Structured Streaming
concepts
Apache Spark
Structured Streaming
lets you build streaming applications and pipelines with the same Spark APIs you use for batch processing. On
Databricks
, it supports two processing modes:
Real-time mode (RTM)
: Designed for sub-second operational workloads, such as fraud detection and real-time personalization. RTM processes records as they arrive, with end-to-end latency as low as five milliseconds. See
Real-time mode concepts
.
Micro-batch mode
: Designed for analytical pipelines and extract, transform, and load (ETL) workloads. Micro-batch mode processes streams in small batches, balancing compute cost with latency requirements measured in seconds or minutes. Micro-batch processing is the default mode.
Both modes use the same
Structured Streaming
APIs. For queries supported by both modes, you can switch modes through the trigger and compute configuration. See
Set up real-time mode
.
Structured Streaming
also powers streaming in
Lakeflow pipelines
, built on
Apache Spark™ Declarative Pipelines
. Pipelines manage orchestration, checkpoints, and recovery, and you define transformations in SQL or Python.
