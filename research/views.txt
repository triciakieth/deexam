CREATE VIEW
Applies to:
Databricks SQL
Databricks Runtime
Constructs a virtual table that has no physical data based on the result-set of a SQL query or a metric view based on a yaml specification.
ALTER VIEW
and
DROP VIEW
only change metadata.
To execute this statement, you must be a metastore administrator or have
USE CATALOG
and
USE SCHEMA
privileges on the catalog and schema, along with
CREATE TABLE
privileges in the target schema.
The user executing this command will become the owner of the view.
warning
CHAR
and
VARCHAR
length semantics, including
CHAR(n)
space-padding, apply only at the table boundary. A view keeps them only for a column passed through unchanged; any expression on the column, such as a
CAST
, function, alias, or added comment, returns plain
STRING
. Because
CHAR
values are space-padded, comparisons can differ from the base table. For example, a
CHAR(10)
value
'COLLEGE'
is stored as
'COLLEGE   '
, so
column = 'COLLEGE'
returns
true
on the table but
false
through the view.
Syntax
​
-- Query-backed or metric view
CREATE [ OR REPLACE ] [ [ GLOBAL ] TEMPORARY ] VIEW [ IF NOT EXISTS ] view_name
[ column_list ]
[ with_clause |
COMMENT view_comment |
DEFAULT COLLATION collation_name |
TBLPROPERTIES clause |
{ COPY | NOCOPY } * |
LANGUAGE YAML ] [...]
AS { query | $$ yaml_string $$ }
-- Temporary view backed by a data source
CREATE [ OR REPLACE ] [ GLOBAL ] TEMPORARY VIEW [ IF NOT EXISTS ] view_name
[ column_list ]
USING data_source [ OPTIONS ( option_key [ = ] option_value [, ...] ) ]
with_clause
WITH { { schema_binding | METRICS } |
( { schema_binding | METRICS } [, ...] } )
schema_binding
WITH SCHEMA { BINDING | COMPENSATION | [ TYPE ] EVOLUTION }
column_list
( { column_alias [ COMMENT column_comment ] } [, ...] )
Parameters
​
OR REPLACE
If a view of the same name already exists, it is replaced. You must be the owner or have
MANAGE
on a view to replace it. The user who replaces the view becomes its new owner.
For a
Unity Catalog
managed view, use the
COPY *
or
NOCOPY *
clause to control whether the replacement preserves the existing view's metadata, such as grants, comments, and tags.
For any other view, replacing it does not preserve privileges granted on the original view or the
table_id
, and is equivalent to
DROP VIEW IF EXISTS view_name
followed by
CREATE VIEW view_name
. Use
ALTER VIEW
to change a view in place without dropping its privileges.
TEMPORARY
TEMPORARY
views are visible only to the session that created them and are dropped when the session ends.
GLOBAL TEMPORARY
Applies to:
Databricks Runtime
GLOBAL TEMPORARY
views are tied to a system preserved temporary schema
global_temp
.
IF NOT EXISTS
Creates the view only if it does not exist. If a view by this name already exists the
CREATE VIEW
statement is ignored.
You may specify at most one of
IF NOT EXISTS
or
OR REPLACE
.
view_name
The name of the newly created view.
A temporary view's name must not be qualified.
The fully qualified view name must be unique.
View names created in
hive_metastore
can only contain alphanumeric ASCII characters and underscores (
INVALID_SCHEMA_OR_RELATION_NAME
).
METRICS
Applies to:
Databricks SQL
Databricks Runtime
16.4 and above
Unity Catalog
only
Identifies the view as a metric view.
The view must be defined with
LANGUAGE YAML
and the body of the view must be a valid yaml specification.
Prior to
Databricks Runtime
17.2, this clause is not supported for temporary views.
A metric view does not support the
DEFAULT COLLATION
and
schema_binding
clauses.
The YAML specification of the metric view defines
dimensions
,
measures
, and optional
parameters
.
The
dimensions
are the columns of the view by which the invoker can aggregate the measures, while the
measures
define the aggregations of the view.
The invoker of a metric view uses the
measure
expression to access the views defined measures instead of specifying aggregation functions.
Preview
This feature is in
Public Preview
.
Optionally, the YAML specification defines
parameters
: named values that the invoker binds at query time. Each parameter has a name, a data type, and an optional default value. Reference a parameter by name in
dimensions
and
measures
expressions, then pass values as named arguments when you query the view as a
table-valued function
. Parameters require
Databricks Runtime
18.2 and above. For the YAML syntax, see
parameters
.
schema_binding
Applies to:
Databricks Runtime
15.3 and above
Optionally specifies how the view adapts to changes to the schema of the query due to changes in the underlying object definitions.
This clause is not supported for temporary views, metric views, or
materialized views
.
SCHEMA BINDING
The view will become invalid if the query column-list changes except for the following conditions:
The column-list includes a star clause, and there are additional columns. These additional columns are ignored.
The type of one or more columns changed in a way that allows them to be safely cast to the original column types using implicit casting rules.
SCHEMA COMPENSATION
The view will become invalid if the query column list changes except for the following conditions:
The column-list includes a star clause, and there are additional columns. These additional columns are ignored.
The type of one or more columns changed in a way that allows them to be cast to the original column types using explicit ANSI cast rules.
This is the default behavior.
SCHEMA TYPE EVOLUTION
The view will adopt any changes to types, in the query column list, into its own definition when the SQL compiler detects such a change in response to a reference to the view.
SCHEMA EVOLUTION
This mode behaves like
SCHEMA TYPE EVOLUTION
, and also adopts changes in column names, column comments, or added and dropped columns if the view does not include an explicit
column_list
.
The view will only become invalid if the query can no longer be parsed, or the optional view
column_list
does not match the number of expressions in the
query
select-list anymore.
column_list
Optionally labels the columns in the query result of the view.
If you provide a column list the number of column aliases must match the number of expressions in the query or, for metric views, the YAML specification.
In case no column list is specified aliases are derived from the body of the view.
column_alias
The column aliases must be unique.
column_comment
An optional
STRING
literal describing the column alias.
view_comment
An optional
STRING
literal providing a view-level comments.
DEFAULT COLLATION
collation_name
Applies to:
Databricks SQL
Databricks Runtime
16.3 and above
Defines the default collation to use within
query
.
If not specified, the default collation is derived from the schema in which the view is created.
This clause is not supported for metric views.
TBLPROPERTIES
Optionally sets one or more user defined properties.
COPY * or NOCOPY *
Applies to:
Databricks SQL
Databricks Runtime
18.3 and above
Unity Catalog
only
Controls whether replacing an existing view with
OR REPLACE
preserves the existing view's metadata, such as its grants, comments, and tags.
COPY *
preserves the existing view's metadata.
NOCOPY *
drops the existing view's metadata. The replacement keeps only the metadata in the new definition.
Only the
*
form is supported: the clause applies to every category of preservable metadata, not a subset. This clause is supported only for
Unity Catalog
managed views, and only with
OR REPLACE
. Using it on any other view raises an error.
If you omit the clause, the default depends on the runtime:
In
Databricks Runtime
18.3, the existing view's metadata is not preserved, the same as
NOCOPY *
. Specify
COPY *
to preserve it.
In
Databricks Runtime
19 and above, the existing view's metadata is preserved by default, the same as
COPY *
. Specify
NOCOPY *
to drop it.
AS
query
A query that constructs the view from base tables or other views.
This clause is not supported for metric views.
AS $$ yaml_string $$
A yaml specification that defines a metric view.
USING data_source
Backs the view directly with a data source instead of a query, so you can query files without first defining a table.
This clause is supported only for
TEMPORARY
and
GLOBAL TEMPORARY
views and can't be combined with
AS
.
data_source
must be a file format, such as
CSV
,
JSON
,
PARQUET
,
AVRO
,
ORC
, or
TEXT
.
For the full list of supported file formats, see
CREATE TABLE [USING]
.
OPTIONS
Sets one or more data source options as key-value pairs, such as the file
path
, whether the file has a
header
, and the parser
mode
.
For the options supported by each format, see the corresponding format reference, for example
Read and write CSV files
.
