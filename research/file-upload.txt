Work with files in
Unity Catalog
volumes
This page has examples for managing files in
Unity Catalog
volumes
for various user interfaces, tools, libraries, and languages.
note
Available in Beta, use the
FILE
type to reference files in volumes as values in a table and apply table access controls to them. See
FILE type and unstructured data
.
Databricks recommends using volumes for managing all access to non-tabular data in cloud object storage and for storing workload support files. Examples include the following:
Data files for ingestion, such as CSV, JSON, and Parquet
Text, image, and audio files for data science, ML, and AI workloads
CSV or JSON artifacts written by
Databricks
for integration with external systems
Libraries, init scripts, and build artifacts
Volumes provide Portable Operating System Interface (POSIX)-style paths that work with Filesystem in Userspace (FUSE)-dependent tools and frameworks. This makes them ideal for machine learning frameworks and open source Python modules that require POSIX-style access. For detailed information about URI schemes, POSIX paths, and how they relate to volumes, see
Do I need to provide a URI scheme to access data?
.

Upload files to a volume
​
You can upload files of any format—structured, semi-structured, or unstructured—to a volume. Volumes support files up to the maximum size supported by the underlying cloud storage. However, when you upload files to a volume through the

Edit files in a volume
​
You can open a text file stored in a volume in the
Databricks
file editor and edit it in place, without downloading the file and uploading it again. The editor saves your changes to the volume automatically.
To open a file in the editor, you need these privileges:
READ VOLUME
on the volume
USE SCHEMA
on the parent schema
USE CATALOG
on the parent catalog
WRITE VOLUME
on the volume to save changes. For details, see
Unity Catalog
privileges reference
.
To edit a file in a volume:
In Catalog Explorer, browse to the volume that contains the file.
Click the
kebab menu next to the file name, and then click
Open in Editor
.
You can also click the file name to open its preview, and then click the
Open in Editor
icon.
Edit the file. The editor saves your changes to the volume automatically.
You can also open a volume file from a notebook or the SQL editor. In the
schema browser
, hover over the file, click the
kebab menu, and then click
Open file
.
If the file changes outside the editor while you have it open, the editor shows a
Conflict detected
dialog. Click
Yes, I would like to fetch the latest changes
to load the latest version of the file, or click
No, overwrite contents
to save your version over it.
In the editor, you can use
Genie Code
to read and edit the file.
Genie Code
can edit only the file that is open in the editor, and only if you have
WRITE VOLUME
on the volume.
Supported file types
​
The editor opens files with these extensions:
Text files
: txt, log, md
Code files
: py, scala, sql, r, sh
Semi-structured data files
: json, ndjson, jsonl, csv, tsv, tab
Configuration files
: yaml, yml, toml, ini, conf, properties, env
Files named
stdout
or
stderr
also open in the editor.
Limitations
​
The editor has these limitations:
If a file is larger than 10 MB, you can't open it in the editor. To edit the file, download it, edit it locally, and upload it again.
If a file has an extension that isn't in the preceding list, such as an image, PDF, or Parquet file, you can't open it in the editor. You can still preview supported formats such as images, PDFs, and Parquet files. See
Preview files in volumes
.
The file editor isn't available in AWS GovCloud regions.

Programmatically work with files in volumes
​
Read and write files in volumes from all supported languages and workspace editors using the following format:
/Volumes/catalog_name/schema_name/volume_name/path/to/files
You interact with files in volumes in the same way that you interact with files in any cloud object storage location. That means that if you currently manage code that uses cloud URIs, DBFS mount paths, or DBFS root paths to interact with data or files, you can update your code to use volumes instead.
note
Volumes are only used for non-tabular data. Databricks recommends registering tabular data using
Unity Catalog
tables and then reading and writing data using table names.

DataFrame checkpoints in volumes
​
You can use
Unity Catalog
volume paths to store
DataFrame checkpoints
. DataFrame checkpoints truncate the execution plan of a DataFrame and save the contents to storage. This can improve performance for iterative algorithms and complex query plans by preventing excessively long lineages when reusing DataFrames.
Storing checkpoints in
Unity Catalog
volumes applies governance and access controls to your checkpoint data, helping you move away from unmanaged cloud storage paths.
Requirements
​
Databricks Runtime
18.1 or above.
Unity Catalog
-enabled compute with either dedicated or standard access mode. DataFrame checkpoints in volumes are not supported on serverless compute.

When using

Limitations of working with files in volumes
​
Before working with files in volumes, consider the following limitations:
Direct-append or non-sequential (random) writes are not supported. This affects operations like writing Zip and Excel files. For these workloads:
